## Что такое Tsuba

Tsuba (鍔, цуба — гарда японского меча) охраняет момент, когда незнакомый код запускается впервые. Поддельные проекты для собеседований, фальшивые программы для встреч, заражённые пакеты npm и вредоносные расширения редакторов каждый раз приходят в новой упаковке и используют обычные инструменты вроде node, curl и bash, поэтому традиционные антивирусы редко их замечают.

Tsuba встаёт в тех точках, где такой код запускается впервые: выясняет, **что код собирается сделать, откуда он взялся и похож ли он на известную атаку**, затем выносит вердикт — **Разрешить, Предупредить или Заблокировать** — и для каждого вердикта показывает файл, строку и правило.

## Почему Tsuba

- 🛡️ **До запуска, а не после.** `curl | bash`, `npm install`, `git clone`, новый DMG в «Загрузках», только что установленное расширение или MCP-сервер: каждое проверяется в тот момент, когда оно впервые запустилось бы.
- 🧠 **Сначала офлайн-правила, потом ИИ с учётом контекста.** Локальные правила и данные об угрозах работают всегда. Затем передовая модель изучает доказательства, чтобы отсеять ложные тревоги и поймать то, чего ещё не знает ни одно правило, — и она никогда не разрешит то, что правила сочли опасным.
- 🔑 **Без нового аккаунта.** Используется Claude Code или Codex, в которые вы уже вошли на своём Mac, либо любой из двух десятков провайдеров с вашим ключом, либо вообще без модели.
- 🔒 **Только чтение по замыслу.** Проверяемый код разбирается, но никогда не запускается: образы дисков подключаются только для чтения, удалённые скрипты загружаются, но не выполняются, а выполняется ровно тот скрипт, который проверила Tsuba.
- 🤫 **Тихо, пока не важно.** Предупреждения беззвучно попадают в историю; только блокировка сопровождается коротким сигналом. Всё, что оказалось ложной тревогой, можно игнорировать или отметить как безопасное.
- 🔄 **Обновляется сама и безопасно.** Новые версии устанавливаются из GitHub Releases, только если их подпись совпадает с ключом Tsuba.
- 🌏 **Говорит на вашем языке.** Приложение, уведомления, проверки в терминале, пояснения правил и ответы ИИ доступны на English, 简体中文, 繁體中文, 日本語, 한국어, Español, Français, Deutsch, Português и Русский. Язык берётся из macOS, или выберите его в «Настройки → Оформление».

## Установка

Скачайте DMG со страницы [Releases](https://github.com/chihyungchang/Tsuba/releases) (macOS 13 или новее): `Tsuba_*_aarch64.dmg` для Mac на Apple silicon (M1 и новее), `Tsuba_*_x64.dmg` для Mac на Intel. Аккаунт не нужен; для проверки ИИ можно использовать Claude Code или Codex, в которые вы уже вошли на своём Mac. Начиная с 0.2.0 новые версии устанавливаются прямо из приложения («Настройки → О программе и обновления» или «Проверить обновления…» в строке меню).

> [!WARNING]
> **Сборки пока не подписаны и не нотаризованы Apple.** При первом открытии macOS заблокирует приложение: откройте **Системные настройки → Конфиденциальность и безопасность** и нажмите **Всё равно открыть**.
>
> Tsuba — open source, так что вы можете проверить, что запускаете: сравните DMG с `SHA256SUMS.txt`, приложенным к каждому релизу (`shasum -a 256 Tsuba_*.dmg`), изучите [workflow](.github/workflows/release.yml), который его собрал, или соберите сами (см. «Выпуск релиза» в разделе [Разработка](#development)).
>
> Пожалуйста, не снимайте карантинный флаг с помощью `xattr`: Tsuba предупреждает об установщиках, которые просят об этом, и её собственный не должен быть исключением.

## Что проверяется

| Точка входа | Примеры | Что проверяется |
| --- | --- | --- |
| Команды терминала | `curl … \| bash`, `npm install`, `npx`, `npm start`, `code .`, `git clone` | Загружает удалённый скрипт (не запуская его) и прослеживает следующую стадию; дату создания пакета npm, период ожидания после релиза и скрипты установки; скрытый код, жёстко заданные C2-адреса и чтение кошельков и хранилищ паролей в исходниках проекта; задачи VS Code, которые запускаются автоматически при открытии папки |
| Вставка в терминал | Веб-страница просит «скопировать эту команду в терминал» | Предупреждает в момент вставки, без выхода в сеть; команды, обфусцированные base64 и переданные в оболочку, сразу помечаются как высокий риск |
| Папка «Загрузки» | Новые файлы `.dmg`, `.pkg`, `.vsix` | Подключает их только для чтения и проверяет подпись, нотаризацию, источник загрузки, не подменён ли основной исполняемый файл скрытым, и скрипты установки |
| Расширения редакторов | Новые или обновлённые расширения в VS Code, Cursor, Windsurf, VSCodium | Официальный список вредоносных расширений, активация при запуске, код, спрятанный в невидимых символах Unicode, подозрительный доступ к сети и файлам; опасные расширения автоматически перемещаются в карантин |
| ИИ-инструменты для кода | MCP-серверы, навыки и хуки плагинов для Claude Code, Cursor, Codex и других; `.mcp.json`, хуки и `CLAUDE.md` в проектах | Есть ли запускаемый пакет в списке вредоносных, не стартует ли он из временной или скрытой папки, какие секреты получает; не прячут ли навыки и описания инструментов указания для ИИ (tool poisoning), не просят ли скрывать что-то от пользователя, читать закрытые ключи или выносить данные |
| Диагностика | Строка меню → Диагностика | Следы известных атак, подозрительные объекты входа, быстрое сканирование установленных расширений |
| Сканирование папки | Страница «Сканирование» или `tsuba scan <folder>` | Установщики, скрипты, расширения и проекты с точками автозапуска в «Загрузках», на внешних дисках и в папках с кодом; уже просканированные неизменённые файлы пропускаются, а «Загрузки» по умолчанию пересканируются с новейшими правилами раз в 7 дней |

Чтобы спросить «почему это заблокировано?» прямо в Claude Code: `claude mcp add tsuba -- tsuba mcp`. Это MCP-инструмент только для чтения: он может лишь смотреть историю проверок и карантин и ничего не меняет. Возвращаемые им команды и сводки помечены как недоверенные данные, а секреты всегда скрыты.

Всё, что оказалось ложным срабатыванием, можно «отметить как безопасное» — тогда отпечаток содержимого попадает в список разрешённых; если содержимое изменится, оно будет проверено снова. Подозрительные файлы, папки и расширения можно переместить в карантин, а затем в любой момент восстановить или удалить.

Расширения, установленные из магазина расширений, не проходят через терминал, поэтому их можно проверить только сразу после установки. Программы, открытые двойным щелчком в Finder, пока заблокировать нельзя: для этого нужно разрешение Apple на Endpoint Security (см. раздел 12 PRD).

## Оценка ИИ

Офлайн-правила всегда срабатывают первыми, а затем ИИ выносит оценку поверх них с учётом контекста. В настройках можно выбрать:

- **Аккаунт инструмента для кода** (рекомендуется): Claude Code или Codex, в которые вы уже вошли на своём Mac. Передовые модели, никаких API-ключей.
- **API-ключ**: Claude, OpenAI или Gemini, разработчики моделей вроде DeepSeek, Qwen, Kimi и GLM, платформы вроде OpenRouter и SiliconFlow, локальные модели через Ollama, LM Studio или vLLM, либо любой эндпоинт, совместимый с OpenAI Chat Completions API.
- **Только офлайн-правила**: без доступа к сети и без вызовов моделей.

Модели делятся на два уровня доверия. Открытые исследования показывают, что передовые модели заметно лучше распознают вредоносный код, а непередовые дают больше ложных срабатываний и легче поддаются prompt injection в коде:

| | Передовые модели (Claude, OpenAI / Codex, Gemini или модель, вручную отмеченная на своём эндпоинте или платформе) | Локальные и другие модели |
| --- | --- | --- |
| Могут сами рекомендовать «Заблокировать» | Да | Нет, максимум «Предупредить» |
| Могут понизить риск, найденный офлайн-правилами | Могут понизить «Заблокировать» до «Предупредить», но не сразу до «Разрешить» | Нет |

Перед отправкой модели из кода удаляются комментарии (чтобы обезвредить prompt injection, спрятанную в них); если доказательства слишком длинные, от каждого текста сохраняются начало и конец, а срабатывания офлайн-правил всегда передаются целиком. Модель получает только те доказательства, которые нужны для этой оценки; другие файлы, переменные окружения и секреты не отправляются. Настройки и история проверок хранятся в `~/.tsuba`.

<a id="threat-intel"></a>
## Данные об угрозах

Помимо офлайн-правил, Tsuba раз в день обновляет данные об угрозах из открытых источников и хранит их в `~/.tsuba/intel` (можно также выполнить `tsuba intel update` в терминале):

| Источник | Содержимое | Лицензия |
| --- | --- | --- |
| [OpenSSF Malicious Packages](https://github.com/ossf/malicious-packages) | Около 230 000 подтверждённых вредоносных пакетов npm / PyPI; транзитивные зависимости в lock-файлах тоже проверяются | Apache-2.0 |
| [OSV.dev](https://osv.dev) (онлайн, можно отключить) | То же, но с запросом в реальном времени во время проверки; отправляются только имя и версия пакета | - |
| Официальный список вредоносных расширений VS Code | Вредоносные расширения, удалённые Microsoft | - |
| Правила YARA от [Elastic](https://github.com/elastic/protections-artifacts) и [ReversingLabs](https://github.com/reversinglabs/reversinglabs-yara-rules) | Сигнатуры известных семейств вредоносного ПО | Elastic License 2.0 / MIT |
| Правила YARA от [GuardDog](https://github.com/DataDog/guarddog) | Подозрительные приёмы, типичные для вредоносных пакетов (только как доказательства; сами по себе никогда не вызывают «Предупредить») | Apache-2.0 |
| Локальные правила XProtect | Собственные сигнатуры вредоносного ПО от Apple, используются только на этом Mac | Apple |
| [VirusTotal](https://www.virustotal.com) (по желанию, ваш ключ) | Вердикты 70+ антивирусных движков по установщикам, программам и удалённым скриптам; отправляются только хеши, файлы никогда не загружаются | Бесплатный API не допускает коммерческого использования |
| [abuse.ch](https://abuse.ch) ThreatFox / URLhaus (по желанию) | Вредоносные домены, IP-адреса и URL; нужен бесплатный Auth-Key, бесплатный тариф только для некоммерческого использования | - |

Правила компилируются и выполняются с помощью [YARA-X](https://github.com/VirusTotal/yara-x). Пакет правил, загруженный по URL пакета правил, применяется, только если у него есть действительная подпись (`tsuba.sig`, ed25519) и его версия не старше используемой; для релиза он подписывается командой `tsuba rules sign --key <private key file> <rules directory>`. Собственные правила обнаружения Tsuba тоже не зашиты в код: они лежат в [crates/engine/rules/tsuba.yar](crates/engine/rules/tsuba.yar) и [tsuba.toml](crates/engine/rules/tsuba.toml) и могут обновляться отдельно.

Правила разработки описаны в [CLAUDE.md](CLAUDE.md).

## В терминале

```bash
tskip npm install          # skip the check this one time
export TSUBA_DISABLE=1     # turn it off for the current terminal window
```

Отменённые команды остаются в истории оболочки; убедившись, что они безопасны, верните их стрелкой вверх.

Каждая команда `tsuba` принимает `--lang <code>` (`en`, `zh-Hans`, `zh-Hant`, `ja`, `ko`, `es`, `fr`, `de`, `pt-BR`, `ru`); без него терминал использует язык, выбранный в приложении.

### Пробный запуск в песочнице (прототип)

Если вы не уверены в скрипте, можно ненадолго запустить его в песочнице и посмотреть, что он на самом деле делает, вместо того чтобы читать код строка за строкой:

```bash
tsuba sandbox install.sh
```

Запуск идёт во встроенной песочнице macOS: настоящая домашняя папка закрыта, и программа видит только поддельную домашнюю папку с приманками; каждый сетевой запрос записывается локальным прокси и на самом деле никуда не уходит; запуск длится не больше 60 секунд. Чтение секретов-приманок и их отправка, запись объектов входа и подключения к голым IP-адресам — всё это фиксируется. Учтите: если за короткий запуск ничего плохого не замечено, это не гарантирует безопасность.

В песочнице можно также пробно запустить папку проекта (`tsuba sandbox ~/code/interview-project`): выполняется его команда запуска, а поведение отслеживается; вредоносный код из проектов для собеседований, который «запускается, как только вы его открыли», здесь себя выдаёт. Добавьте `--install`, чтобы попробовать установить зависимости (`npm install`) в песочнице и увидеть, что делают их скрипты установки; в этом режиме пропускаются только загрузки из официального реестра npm, а все остальные подключения по-прежнему лишь записываются. Песочница на виртуальной машине для DMG и приложений пока не сделана.

## Разработка

```
Tsuba/
├── Cargo.toml              Rust workspace

│   ├── engine/             Detection engine (tsuba-engine): recognition, evidence collection, offline rules, threat intel, AI judgment

    ├── src/                UI (React + TypeScript)
    └── src-tauri/          App back end: tray, windows, background monitoring, terminal integration
```

</details>

Нужны Rust (`rustup`), Node.js и pnpm.

```bash
pnpm app                                     # start the app (installs front-end dependencies first)
cargo test                                   # run the engine tests
cargo run -p tsuba-cli -- scan <path>        # check a file or directory directly, without the app
cargo run -p tsuba-cli -- eval <samples dir> # sample set acceptance: detection and false positive rates against the targets in PRD section 4
```

Папка образцов содержит две подпапки, `malicious/` и `benign/`; каждый файл или подпапка считается одним образцом (подходят проекты, расширения, установщики и скрипты, а также символические ссылки). Используются только офлайн-правила, поэтому результаты воспроизводимы; если цели не достигнуты, код выхода равен 1, так что это можно встроить в CI. Чтобы разделить образцы по времени, положите старые и новые в две папки и запустите их по отдельности.

При разработке приложение ищет модуль проверки для терминала рядом с собой (`target/debug/tsuba`); подключите его одним нажатием в «Настройки → Защита → Подключить к zsh» — это подействует в новых окнах терминала.

Все тестовые образцы безвредны: они лишь повторяют форму вредоносного кода, их IP-адреса взяты из диапазонов для документации, а декодированное содержимое тоже безопасно.

В коде хранится английский текст; переводы лежат в отдельном каталоге для каждого языка (`locales/<code>.json` в `app/src`, `app/src-tauri`, `crates/engine` и `crates/cli`), а у каждого правила в пакете правил есть собственный `message_<lang>`. Тесты каталогов и `pnpm check:i18n` падают, если строки нет хотя бы в одном языке или перевод потерял `{placeholder}`.

Иконка приложения, ноутбук на панели и страж-цуба — рендеры Blender: в `app/src-tauri/icons/source/` лежат скрипты и шаги для их пересоздания.

<summary><b>Выпуск релиза</b></summary>

```bash
cd app && pnpm release --bundles app   # local release build for this Mac, terminal checker included
```

Релизная сборка содержит модуль проверки для терминала в виде `Tsuba.app/Contents/MacOS/tsuba`. Его добавляет `tauri.release.conf.json`, который запускает `app/scripts/build-cli-sidecar.sh`; в `tauri.conf.json` его нет, потому что без этого файла Tauri отказывается собирать проект, и это сломало бы `cargo test`.

Чтобы опубликовать релиз, выполните `scripts/release.sh X.Y.Z` на чистой `main`: скрипт выставляет версию в корневом `Cargo.toml` (единый источник версии для приложения, CLI и DMG), прогоняет проверки перед коммитом, делает коммит, ставит тег `vX.Y.Z` и спрашивает перед push. Тег запускает `.github/workflows/release.yml`, который прогоняет тесты и одновременно на трёх раннерах собирает DMG для Apple silicon и Intel, прикрепляя их и `SHA256SUMS.txt` к черновику GitHub Release с заметками, составленными по коммитам, и публикует его, когда все задачи прошли (заодно пересобирается сайт). Если какая-либо задача упадёт, черновик удаляется, а тег остаётся. Ручной запуск workflow (Actions → Release → Run workflow или `gh workflow run release.yml`) — это пробный прогон, который сохраняет DMG как артефакты workflow.

Обновления в приложении берутся из тех же релизов: «Настройки → О программе и обновления» проверяет `latest.json` последнего опубликованного релиза (Tsuba также тихо проверяет при запуске), загружает пакет для этого Mac и устанавливает его, только если подпись совпадает с открытым ключом в `tauri.conf.json`. CI создаёт подписанные пакеты и `latest.json`, когда секрет репозитория `TAURI_SIGNING_PRIVATE_KEY` содержит закрытый ключ обновлений (создаётся командой `pnpm tauri signer generate`, без пароля). Сохраните резервную копию этого ключа: без него установленные копии больше никогда не смогут обновиться.

Подпись и нотаризация выполняются, когда заданы секреты репозитория: `APPLE_CERTIFICATE` (.p12 в base64), `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (пароль приложения) и `APPLE_TEAM_ID`. Без них DMG не подписан, и Gatekeeper блокирует его после загрузки.
